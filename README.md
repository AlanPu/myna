# Myna

AI 口语跟读播放器。把一个 YouTube 视频变成可以逐句慢速跟读的材料:音频按原速播放,字幕逐词高亮跟随人声,任意一句可以循环重复。

不依赖 TTS。慢速版本用 `atempo` 渲染,保留原始音色和音高——跟读要练的是**你的发音**,不是模仿一个合成声音。

## 快速开始

```bash
./play.sh                 # 打开 http://127.0.0.1:8777/index.html
```

页面上方的「换视频」可以直接粘贴新的 YouTube 网址重建。留空则继续用当前视频,时长填 `0` 表示截取完整音频。

手动重建:

```bash
export https_proxy=http://127.0.0.1:7890        # 需要代理时
.venv/bin/python rebuild.py "<url>" 0 180 "标题"    # url / 起点 / 时长(0=完整) / 标题
```

`rebuild.py` 跑完会自动执行验证,任何一项不过就返回非零并拒绝交付。

## 流程

```
rebuild.py
  1 下载音频(按视频 ID 缓存)
  2 抓字幕 → 重新分组为句子          sentences.py
  3 切片
  4 渲染 4 档变速(atempo,保音高)
  5 实测每句语音边界 + 逐词标记      onsets.py wordmarks.py
  6 写清单
  7 跑四项验证                      check.py
```

`serve.py` 提供静态文件和一个 `POST /api/build`,让浏览器能触发生成并实时显示日志。

## 这个项目最难的部分

高亮必须**跟着人声走**,而不是跟着字幕时间戳走。这两件事不一样,而且差得很远。

**字幕窗口是滚动的,会重叠。** 自动字幕按"显示时长"切段,一段字幕会在下一段开始后仍然挂着。18 分钟的片段里 229 对相邻句子中 120 对窗口重叠,平均提前约 2 秒开始。所以拿字幕窗口当句子边界,循环跟读时会把下一句的开头混进每一次重复——第一句实际只有 4.44 秒语音,窗口却到 6.40 秒。

**高亮的粒度问题在词,不在句。** 自动字幕的时间戳只到句,没有词级信息。`wordmarks.py` 用 RMS 包络 + 音节核检测找出 5377 个候选峰,再按时间把峰切分给每个词,每段取其中能量最高的那个。当前构建 3048 个词全部落位。

**验证必须来自波形,不能来自数据自洽。** 这一条花了最久。早期写的检查都是把播放器和它自己的数据对比,结果连续三次报告"通过"而实际高亮明显滞后。这些检查**在结构上就无法发现滞后**。现在只有两项检查是有信息量的:

| 检查 | 判据 |
|---|---|
| `verify_switch.py` | 每句的最后一个词在被替换前必须点亮 |
| `verify_visual.py` | 每个标记之后 250ms 内必须有真实语音 |

当前构建:230 句,18.4 分钟。231 次切换中 229 句词全亮;3026 个词标记里 93% 后面跟着真实语音,59% 是明显发声的帧。

## 已知的取舍

**句间真实重叠。** 229 对相邻句子里有 120 对在录音里本来就重叠,最多到 4.08 秒。重叠期间屏幕显示的是上一句,而新句的语音已经开始。这是录音的属性,消除它需要改动切分逻辑,收益不明确。

**7% 的词标记落在换气停顿里。** 逐帧核对过,是真的停顿,不是 bug。高亮应该比声音早一点点亮。

**长片段的检查阈值。** 3 分钟片段零容忍成立,18 分钟下 0.9% 的句子因上述重叠丢词。`verify_switch.py` 因此按 2% 判定并打印最差情况。

## 依赖

Python 3.12、`ffmpeg`、`yt-dlp`、`youtube-transcript-api`,浏览器检查需要 Playwright。慢速渲染不需要 `rubberband`。

`.venv/`、`audio2/`、`player/*.m4a` 和变速产物不入库——都由 `rebuild.py` 生成。
